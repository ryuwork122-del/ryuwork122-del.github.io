Automation Agent Platform

An LLM agent that reads inbound requests, classifies intent and executes multi-step workflows against internal APIs — with a human approval gate on anything destructive.

Year2026

The problem

A small operations team was spending most of every day on the same loop: a request arrives by email or form, someone reads it, decides which of four internal systems it touches, re-types the relevant fields into each one, and replies. It was high-volume, low-judgement work — exactly the kind that should not need a person, except that the edge cases genuinely did.

The goal was not "replace the team with a chatbot." It was to let the routine 80 percent flow through automatically while making the remaining 20 percent faster and safer to handle by hand.

Approach

Everything starts with typed tools. Each action the agent can take — create_record, lookup_customer, send_reply, schedule_followup — is a function with a strict input schema. The model never writes a query or calls an endpoint directly; it chooses a tool and supplies arguments that are validated before anything runs.

A request flows through four stages: normalise the raw input, retrieve context (customer history, open tickets, policy docs), let the model produce a plan as a sequence of tool calls, then execute. A queue-based dispatcher runs the calls and logs every step with the input, output and latency attached.

The part that made it trustworthy was the gate. Any action flagged high-impact — refunds, deletions, anything touching billing — pauses the run and posts an approval request with the proposed arguments and the model's reasoning. A human clicks approve or reject, and the decision is recorded as training signal either way.

What was hard

Retries, not the language model. Any workflow that writes to systems of record needs idempotency: a timeout after a successful write must not become a duplicate invoice. Every tool got an idempotency key and an existence check, and the dispatcher marks a step complete only after the write is confirmed.

Confidence scoring came second. A cheap model proposes a classification, and low confidence routes to a human instead of guessing — which turned out to be far more useful than pushing the model's accuracy until it looked impressive in a demo.

Outcome

Routine requests now complete end to end without a person in the loop, and four separate systems write through a single pipeline with a full audit trail. The approval gate caught ordering mistakes and duplicate submissions before they could reach a customer, and every override became documented evidence of where the model's judgement still needed support.

Takeaways

If you are building something similar, the model is the easy part. Design the tool contracts first, make every write idempotent, and decide up front which actions require a human — then let the model do the reading.
